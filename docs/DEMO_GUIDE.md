# StitchRush presentation flow

All physical operations and provider responses are simulated. Do not present the demo as an actual service pilot.

1. Home: choose Shirts & Tops, Shorten sleeves, Sector 56 Gurugram, and a required return date at least three days ahead.
2. Send request to tailors: review the details, choose Cotton, quantity 1 and a return time. Send request to suitable tailors.
3. Tracking: point out that no tailor is selected. Expand Demo controls and click Simulate suitable responses.
4. Compare responding tailors: inspect ratings/review counts (labelled sample), capability, proposed timing and estimated totals. Try sorting by rating or total.
5. View work and offer for Thread & Form. Open a work illustration or correction policy; explain these are examples. Choose this tailor.
6. Select a future pickup slot, acknowledge pending confirmation and Request pickup and fitting. Show the separate pending state.
7. Demo controls: Confirm demo pickup, then Simulate fitting & collection, then Prepare demo final quote.
8. Review final quote: estimated Rs 180-230 becomes a specified sample total of Rs 220. The approval button is disabled until acknowledgement. Optional: Ask to change instructions, save and review again.
9. Approve alteration. Tracking now shows alteration in progress and retains the approved record.
10. Demo controls: Mark alteration ready, Simulate return dispatch, Simulate delivery.
11. Check fit & give feedback. Answer fit and timing separately. Try No, report a fit issue; select an issue and Request a correction. A request does not confirm a pickup.
12. Refresh to demonstrate persistence on this browser. A different device or domain starts with its own empty state.
13. Footer > Inside the design: show the need/barrier/motivation, 12 CB decisions, evidence limitations, AI disclosure and planned A/B experiment.

## Useful alternate scenarios

- Fresh waiting request > Simulate no response. Edit the return deadline or task and resend.
- Offers > Withdraw first offer. The withdrawn provider disappears from the valid results.
- Before confirmed collection > Edit request. Old offers and the pickup selection are invalidated.
- Before submitting a request > tick the simulated failure checkbox, submit, then try again. Values remain.
- Quote review > Decline quote. Alteration cannot proceed; unaltered return arrangements are pending.
- During alteration > Simulate a delay. Original commitment remains and revised timing requires acknowledgement.
- Privacy > Reset demo data to start again. The confirmation prevents accidental reset.

## Suggested explanation

“We ask for the job and deadline before showing choices. Customers compare providers who have provisionally responded, which aims to reduce search effort and availability uncertainty. Work evidence supports perceived-risk evaluation; clear total pricing supports an informed choice. Doorstep assessment records the required fit, and alteration starts only after approval. We measure fit and timing separately after delivery.”

The site does not run the A/B experiment or collect real respondent data. Those remain separate project work.
